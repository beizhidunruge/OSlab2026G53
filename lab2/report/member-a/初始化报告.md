# Lab2 成员 A：物理内存初始化（2414034）

实验日期：2026-10-17。基线：小组仓库 `972abb8`。本章供成员 B 汇总使用。

## 1. 工作范围与执行链

负责 `page_init()`、初始化边界验证以及页表/MMU 调试；First-Fit 使用框架已有实现，Best-Fit、Buddy 由 B、C 完成。本章的 spec 和 AI 协作过程见 [规格与协作记录](spec-and-prompts.md)，两个调试层面的证据见 [MMU 调试报告](MMU调试报告.md)。复现脚本统一位于 `../../Lab2_成员A_2414034/lab2/tools/member_a/`。

执行链：`entry.S → kern_init → memset(BSS) → dtb_init → pmm_init → init_pmm_manager → page_init → init_memmap → check_alloc_page`。启动页表已由汇编构建；`page_init()` 建立物理页管理元数据，不重新构建页表。

必须区分三种对象：物理页是 4 KiB RAM；`struct Page` 是描述它的管理记录，本构建占 40 字节；页表项 PTE 是供 MMU 翻译地址的 8 字节记录。Page 数组与页表都占用 RAM，但两者职责不同。

## 2. 初始化算法与契约

1. 读取 DTB 内存起点和大小。长度为零、起点不符合本框架 `DRAM_BASE`、`base+size` 溢出均 panic。固定起点限制来自启动映射和常量 `nbase`，不能仅替换一个变量就支持任意起点。
2. 设置 `va_pa_offset=0xffffffff40000000`。这是启动页表已经采用的偏移，不能将 DTB RAM 起点与内核虚拟入口直接相减而漏掉固件占用的 2 MiB。
3. 取 DTB 末端、`PHYSICAL_MEMORY_END`、`KERNTOP-va_pa_offset` 的最小值，再向下按 4096 对齐，得到可管理物理末端 `maxpa`。
4. 设置 `npage=maxpa/4096`；它是绝对物理页号上界，描述符数量为 `npage-nbase`。
5. 将 `end` 向上按页对齐作为 `pages` 的虚拟地址，再转换成物理地址。先检查内核范围和数组容量，用 `count <= (maxpa-pages_pa)/sizeof(Page)` 避免乘法/加法溢出，然后才写入数组。
6. 全部描述符先设 reserved，ref/property 清零，链表节点初始化。这样固件、内核、描述符和对齐空隙对应的物理页均不会提前进入空闲链表。
7. 描述符末端向上对齐得到 `freemem`。只有 `freemem<maxpa` 时才调用 `init_memmap(pa2page(freemem),(maxpa-freemem)/PGSIZE)`。区间为空则保留零空闲页状态。

`init_memmap` 将这段完整空闲页交给当前分配器。框架 First-Fit 会清除这些页的 reserved 状态，将连续区间首描述符标为 property，并建立空闲链表。其他描述符仍保留。

## 3. 默认 128 MiB 的真实布局

证据：`logs/first-fit-128M.txt`、`logs/layout.txt`。

| 项目 | 实测值及计算 |
| --- | --- |
| DTB RAM | `[0x80000000, 0x88000000)` |
| 内核虚拟入口 | `0xffffffffc0200000` |
| 启动根页表物理地址 | `0x80205000` |
| 内核 `end` 虚拟地址 | `0xffffffffc0206078` |
| Page 数组虚拟起点 | `0xffffffffc0207000` |
| Page 数组物理起点 | `0x80207000` |
| `nbase` / `npage` | `0x80000` / `0x88000` |
| 描述符数量 | `0x88000-0x80000=32768` |
| 描述符大小 | `sizeof(Page)=40` 字节（包含结构体对齐填充） |
| 数组字节数 | `32768×40=1310720=0x140000` |
| 空闲区 | `[0x80347000,0x88000000)` |
| 保留 / 空闲页数 | `839 / 31929`，合计 32768 |

这里 `npage` 不是 32768，也不是空闲页数。地址换算为 `page2pa(p)=(p-pages+nbase)<<12`，`pa2page(pa)=&pages[(pa>>12)-nbase]`；调用必须遵守物理地址在管理区间内的前提。

| 输入 | 预期与实际结果 |
| --- | --- |

## 5. 实际问题与解决

### 未实现的 Best-Fit 阻塞编译

仓库原始 `best_fit_pmm.c` 只有两个检查函数，却引用尚未定义的 `free_list` 和 `nr_free`。Makefile 收集整个 mm 目录，因此即使选 First-Fit 也会编译失败。验证脚本复制隔离副本时排除这个尚未实现的 `.c` 文件，使用原 First-Fit 完成 A 的验收；B/C 源码和测试函数保持完整。B 完成模块后可正常统一编译。

### 开启分页后仍从未映射的低地址取指

原始入口只映射根页表第 511 项对应的高地址区，却在写 satp 后继续从 `0x80200038` 取指。GDB 捕获到 satp 已为 `0x8000000000080205`，但不能访问该低地址；串口停在 OpenSBI，没有进入内核。原始故障证据保存于 `original-entry-gdb.txt` 和 `original-entry-failure.txt`。

修复：在开启分页前把 `stvec` 设置为高地址 `paging_enabled`；分页切换后的首次低地址指令页故障转入这个已映射的高地址入口。同时在 satp/sfence 后增加显式 `jr t2`，兼容旧模拟器继续执行已翻译的低地址指令块的情况。高地址入口按 4 字节对齐，执行 `sfence.vma`、清理临时 stvec，再设置栈并进入 C 代码。这个最小启动补充保留了原有“只有第 511 项有效”的根页表布局，没有额外建立三级表。异常路径依赖平台向 S 模式委托指令页故障，本次 OpenSBI/QEMU 环境满足该条件。两版差异的实际定位见 MMU 调试报告。

### GDB 优化源码断点重复计数

最初用函数名设置 `default_init_memmap` 断点，GDB 为优化后的函数产生两个断点位置，导致调用计数断言失败。改用 `*default_init_memmap` 在精确机器入口断住，重新运行全部边界场景通过。没有修改初始化代码来迁就测试。

## 6. 选做思考：未知硬件内存范围如何获取

优先使用平台提供的可信内存描述：本实验由 QEMU 构造设备树、固件通过 a1 传入 DTB 地址，OS 解析 memory 节点的 reg；其他平台可由 UEFI 内存映射、传统 BIOS E820 或引导协议提供范围。应同时处理可用 RAM、固件保留区、MMIO 和内核占用，不能把最大地址以下全部当成 RAM。

实际系统还要支持多个不连续内存区、reserved-memory 和设备树保留表，并在整数溢出、重叠、对齐及边界检查后登记。主动试写未知地址可能触发总线错误或设备副作用，不能作为通用可靠的探测方式。本实验简化解析器只提取一个 memory 区间，初始化后允许回收 DTB 本身空间；没有声称实现生产级设备树健壮性。

## 7. OS 原理对应与局限

本模块对应物理内存发现、页粒度资源管理、保留区保护和元数据自举。启动页表负责 VA→PA，Page 数组负责物理页状态，两种机制协同但不能互相代替。当前未实现用户地址空间、进程切换、换页、多核并发分配和通用热插拔，也没有设计新的 Best-Fit/Buddy 策略。
