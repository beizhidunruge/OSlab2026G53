## 1. 本部分在实验主线中的位置

本实验首先要确定物理内存范围，再组织可用页，最后才能分配和回收。启动汇编已经配置页表并开启 Sv39，`kern_init()` 读取设备树信息后调用 `pmm_init()`。`pmm_init()` 先选择并初始化分配器，再通过 A 实现的 `page_init()` 建立 `Page` 数组、保护固件和内核等占用区，将剩余完整物理页交给分配器，最后执行自检。

```text
pmm_init()
  ├─ init_pmm_manager() → best_fit_init()
  ├─ page_init() → init_memmap() → best_fit_init_memmap()
  └─ check_alloc_page() → best_fit_check() → basic_check()

后续使用：
alloc_pages(n) → best_fit_alloc_pages(n)
free_pages(base, n) → best_fit_free_pages(base, n)
```

因此，本部分解决的是“如何从已确定的空闲物理页中选择连续区间，以及归还时如何恢复可用空间”。它不负责探测硬件、不重新建立页表，也不把物理页描述符当作虚拟地址映射使用。

相关源码为 [default_pmm.c](../code/kern/mm/default_pmm.c)、[best_fit_pmm.c](../code/kern/mm/best_fit_pmm.c)、[pmm.h](../code/kern/mm/pmm.h)、[memlayout.h](../code/kern/mm/memlayout.h) 和 [pmm.c](../code/kern/mm/pmm.c)。

## 2. 任务一：理解 First-Fit 连续物理内存分配

### 2.1 数据结构与状态含义

每个 4 KiB 物理页对应一个 `struct Page` 描述符。描述符数组按物理页号排列，因此 `base + n` 表示后移 `n` 个描述符，也对应后移 `n` 个物理页；它不是对物理内存地址直接加 `n` 字节。

分配器使用 `free_area_t` 保存循环双向链表和空闲页计数。链表按物理地址递增排列，只链接每个连续空闲块的首页。首页的 `PG_property` 标志表示“这是空闲块首页”，`property` 字段记录块长。`nr_free` 是全部空闲页数，不是空闲块数。

例如，链表中有长度分别为 2、7、4 页的三个块，则节点数为 3，`nr_free` 为 13。块内其他页虽然可能空闲，却没有首页标志，因此不能把 `PageProperty(p) == 0` 简单理解为该页一定已分配。`PG_reserved` 则用于保护不允许普通分配的页。

### 2.2 default_init：初始化管理结构

`default_init()` 用 `list_init(&free_list)` 将链表头的前后指针都指向自身，并将 `nr_free` 清零。此时分配器已经具备空的管理结构，但还没有登记可分配物理页。

### 2.3 default_init_memmap：登记初始空闲区

`default_init_memmap(base, n)` 接收上层确认可用的连续页区间。它检查 `n > 0`，逐页确认原先为保留状态，然后清除标志及旧块长，引用计数设为 0。随后设置 `base->property = n` 和首页标志，将 `nr_free` 增加 `n`。

最后，函数按地址找到插入位置，将首页的 `page_link` 加入链表。该函数本身不探测内存，也不判断内核占用区，而是依赖 `page_init()` 传入正确范围。当前 First-Fit 的登记函数只排序插入，没有额外执行相邻登记块合并。

### 2.4 default_alloc_pages：选择第一个满足请求的块

申请 `n` 页时，函数先检查总空闲页数。若总数不足就直接返回 `NULL`；否则从链表头开始遍历，遇到第一个 `property >= n` 的块立即停止。

找到块后将其从链表摘除。如果块长恰好等于请求，则整块交给调用者；如果块更大，就分配前 `n` 页，把剩余区间的首页设为 `page + n`，记录剩余长度并挂回原位置。最后将 `nr_free` 减少 `n`，清除返回页的空闲块首页标志。

这里返回的是首页描述符，不是可直接读写的物理地址。分配器也不负责清空页内容。原 First-Fit 分配后未必清零旧 `property` 数值，所以要结合首页标志判断该字段是否有效。

总页数足够并不保证分配成功。例如两个互不相邻的 2 页空闲块共有 4 页，但不能满足连续 3 页的请求；遍历结束仍返回 `NULL`。这体现了连续分配中的外部碎片问题。

### 2.5 default_free_pages：回收并合并物理相邻块

释放时，`default_free_pages(base, n)` 先检查页面不是保留页，也不是已有空闲块首页，然后重置状态和引用计数，将待释放区间组织为一个新空闲块，并把空闲页数增加 `n`。调用者仍须保证释放区间有效，这些断言不等于完整的非法释放检测。

新块按地址插回后，先检查前驱是否满足 `p + p->property == base`，满足则说明物理相邻，可把两块合为一块，并让 `base` 指向合并后的最低地址首页。再检查新的后继是否满足 `base + base->property == p`，继续合并。

```text
释放前： [空闲 2 页][已分配 3 页][空闲 4 页]
释放后： [               空闲 9 页              ]
```

不能只因链表节点相邻就合并，因为中间可能隔着已分配页。合并只改变空闲块的组织，不再次增加 `nr_free`。

### 2.6 思考：First-Fit 是否还有改进空间

有。设空闲块数为 `k`，当前分配最坏需要扫描 `k` 个块；释放也需要线性查找地址插入位置。可以增加地址索引或维护子树最大空闲块长度，以减少搜索。但要保持“最低地址的第一个可满足块”语义，不能简单改为按大小选择就仍称其为 First-Fit。

碎片方面，当前实现已经合并相邻空闲块，不能将“增加相邻块合并”作为尚未实现的改进。可研究不同分配策略在具体负载下的效果，例如 Next-Fit 或 Best-Fit；它们改变了选择规则，不能保证普遍优于 First-Fit。任何连续分配策略都不能仅靠合并跨过仍被占用的页面。

| 对象 | 前置条件与行为规格要点 |
| --- | --- |
| 初始化 | 尚未登记可用页，建立空链表并清零计数 |
| 登记 | 输入为连续、有效、尚处保留状态的 `n > 0` 页；转为空闲页，设置首页元数据并增加计数 |

| 检查入口 | 注册到现有 `best_fit_check()`，不改写两项框架测试 |

## 4. Best-Fit 核心实现

### 4.1 状态与选择规则

内部仍使用模块静态 `free_area_t`，并用宏提供测试可直接读写的 `free_list`、`nr_free`。空闲块按地址排序，按大小选择；二者是不同职责。使用一个链表既方便合并，也与现有测试的保存和恢复方式兼容。

例如按地址依次存在 2、7、4 页三个块，申请 3 页：First-Fit 选择 7 页块，Best-Fit 选择 4 页块。Best-Fit 的目标是减小这一次分配留下的余量，并不保证整个运行过程中碎片最少。

### 4.2 best_fit_init 与 best_fit_init_memmap

`best_fit_init()` 建立空链表，将计数设为 0。

`best_fit_init_memmap()` 逐页确认保留状态，清除标志和旧块长，引用计数清零。然后设置新块首页及长度，增加 `nr_free`，交给辅助函数完成有序插入和相邻合并。它比原 First-Fit 登记函数多复用了合并处理，但不会把保留页之间的间隔合并进去。

### 4.3 best_fit_insert_free_block

该辅助函数复用于登记和释放，不另行维护空闲页计数。

它先找到第一个地址大于 `base` 的节点，将新块插在它之前；若找不到就插到链表末尾。随后先向前合并，再基于新的首页重新取得后继，完成向后合并。被吸收的首页清除标志、块长并从链表移除，防止残留失效节点。

把计数留给调用者，能避免登记、释放和合并多次增加 `nr_free`。向前合并后重新确定后继，则避免漏掉另一侧可合并块。

### 4.4 best_fit_alloc_pages

选择逻辑的关键部分如下：

```c
if (p->property >= n &&
    (page == NULL || p->property < page->property)) {
    page = p;
    if (p->property == n) {
        break;
    }
}
```

循环维护当前最小可用块。地址递增遍历配合严格的小于比较，使同长度时保留最低地址候选。只有精确匹配已达到最优时提前结束，不会像 First-Fit 那样看到任意足够大的块就停止。

选中后摘除原节点；若有余量，以 `page + n` 为新首页放回原位置，从而维持地址有序。分配区首页清除 `PG_property` 并将旧块长置零，`nr_free` 减少 `n`。空链表或不存在候选块时返回 `NULL`，不更改链表和计数。

### 4.5 best_fit_free_pages 与 best_fit_nr_free_pages

释放函数逐页检查和重置状态，建立 `n` 页块，计数增加 `n` 后调用插入合并函数。不会要求该范围必须对应一次分配，因此与框架先分别分配子区间、再整体释放的行为兼容。

查询函数直接返回 `nr_free`。本实现不依赖额外树索引或缓存，测试只恢复链表和计数时，不会遗漏其他必须同步的管理状态。

### 4.6 管理器注册与接入

`best_fit_pmm_manager` 将上述五项管理操作绑定到框架接口，并将 `.check` 绑定现有 `best_fit_check`。本任务保留 `//lab2 function2-2 2412591` 标记。

后续在 `pmm.c` 的 `init_pmm_manager()` 中设置：

```c
pmm_manager = &best_fit_pmm_manager;
```

该切换使公开的分配、释放、计数和检查入口真正调用 Best-Fit。仅实现注册结构、没有切换管理器时，启动仍可能检查 First-Fit，不能作为 Best-Fit 通过的证据。A 的 `page_init()` 和 `entry.S` 启动修复在合并时原样保留。

## 7. 思考：Best-Fit 是否还有改进空间

有。当前实现以易理解和兼容测试为主。设空闲块数为 `k`，操作涉及 `n` 个物理页，则：

| 操作 | 当前时间复杂度 |
| --- | --- |
| 初始化空管理器、查询页数 | O(1) |
| 分配 | 最坏 O(k)，精确匹配可提前返回 |
| 登记、释放 | O(n + k)：逐页重置及查找地址插入位置 |
| 已定位节点后的两侧合并 | O(1) |

管理节点复用描述符内的 `page_link`，操作不动态分配额外节点，辅助空间为 O(1)；全局 `Page` 数组的存储仍随物理页数量增长，不能把整个物理内存管理系统说成只占 O(1) 空间。

可以考虑按 `(块长, 地址)` 维护有序索引，查询最小满足长度的块，同时保留按地址寻找邻居的结构。合适的数据结构可降低搜索代价，但分裂、合并需要同步更新多处信息，且现有测试只保存和恢复链表与计数，额外索引必须处理兼容问题。该优化仅作分析，当前没有实现。

碎片方面，Best-Fit 只使当前分配剩余的块尽量小，可能产生很多难利用的小块；并不保证优于 First-Fit。可通过不同请求分布比较成功率、搜索长度和最大连续空闲块，而非只比较空闲总页数。当前精确分配页数；如果改成少量余量也整块分配，就会改变释放和计数约定，不能直接套用到本接口。

## 8. 与 OS 原理的对应及未覆盖内容

| 实验知识点 | 对应 OS 原理 | 本实验的体现与边界 |
| --- | --- | --- |
| 连续物理页分配 | 动态分区的空闲块选择 | First-Fit／Best-Fit 在此以页为单位工作，不是任意字节分配 |
| 分裂与相邻合并 | 空闲空间组织与外部碎片 | 保持可复用连续块，但不能跨过占用页合并 |
| Page 描述符和首页元数据 | 资源状态管理 | 元数据与被管理内存分开，非首页标志不能单独判定是否已分配 |
| 分配器接口与回调 | 策略和统一调用接口 | 保持公开调用一致，替换内部选择策略 |
| 物理页与页表 | 物理资源分配和地址转换 | 分配器决定页的归属，页表决定虚拟地址如何翻译，两者不能互相替代 |

与本部分尚未对应的原理包括：进程私有地址空间、按需分页、缺页换入与页面置换、写时复制、多核同步及 TLB shootdown。按页分配也无法直接提供任意字节对象的高效管理；后者属于 SLUB 等对象分配层研究的内容。
